## 裁决清单（5 项，全部已落地）

### 1. 仓位阶梯统一（§1.1）

| | 内容 |
|---|---|
| 原状 | `position_tiers = {startup[10,25], rally[25,60], high>60}`；与 `funnel.probe[0,12]` 在 **10~12 双命中**，同票同时命中"试错仓 1/3"与"建底仓" |
| 裁决 | 二者不是矛盾，是**同一仓位阶梯的两个台阶** → 合并为一张阶梯表 `tiers[4]` + `position_pct` |
| 新结构 | 试错 1/3（探测层信号，chg20d 0~12）→ 底仓 2/3（二级确认 或 chg20d 10~25 且四维≥3）→ 满仓 3/3（25~60 + 四维全绿，≤总资金20%）→ 高位只看不追（>60，仓位 0） |
| 影响 | 语义唯一化；10~12 区间不再双命中（归属"试错→底仓"的过渡台阶，由**二级确认**决定是否加仓，而非区间本身） |

### 2. 确认层收敛 25~60（§1.2）

| | 内容 |
|---|---|
| 原状 | `funnel.confirm.chg20d = [25, 90]`，但 60~90 落进高位档"只看不追" → **白筛 30 个点** |
| 裁决 | 买入筛选收敛为 `[25, 60]`；60+ 一律归高位档；**持有判据不设区间**（四维用于判断"是否继续拿"） |
| 新结构 | `chg20d_max: 90 → 60` |
| 影响 | 与"动量维筛选区间=确认层区间"合并为同一区间；**自动化 prompt 中的筛选命令已同步改为 `< 60`** |

### 3. 生命周期词汇（§1.3）— ⚠️ 与路线图方向相反，已按数据面现状裁决

| | 内容 |
|---|---|
| 原状 | `mainline.lifecycle = null`（配置层未落地）；手册混用（确认 13 次 / 主升 7 次 / 预热 2 次 / 刚起步 2 次 / 扩散尾声 1 次）；台账已统一在**刚起步/主升/尾声/退潮**（预热 0 次） |
| 路线图原建议 | 以「预热/主升/尾声/退潮」为正式词 |
| **实际裁决** | **以「刚起步/主升/尾声/退潮」为正式词**（方向反转） |
| 理由 | ①「刚起步」比「预热」更白话，符合"禁黑话"铁律；②数据面（台账 8 次刚起步、驾驶舱、自动化 prompt）已全量固化，反转要动 4 处且 90 天历史数据需重映射；③路线图自身逻辑（"主升比确认直白"）同样适用于这一对。**裁决成本：仅需改手册 1 个文件，台账零改动** |
| 新结构 | `lifecycle = {stages:[刚起步,主升,尾声,退潮], _map_legacy:{预热→刚起步, 确认→主升, 扩散尾声→尾声}, _stage_rules:{四阶段判据}}` |
| 待办 | 手册 `docs/strategy-handbook.html` 需同步改词（确认→主升、预热→刚起步、扩散尾声→尾声） |
