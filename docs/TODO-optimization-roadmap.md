# fast-trend-trade 优化路线图（v0.1 → v0.2）

> 基于 2026-09-12 全量代码审查 + 方法论评审产出。原则：**不动摇框架核心**（双向锚定 / 三级火箭 / 物种判别 / 期望值结构），只做三类事——裁决语义冲突、补验证体系、挖共振层增量。
>
> 配套阅读：`README.md`（核心原则）、`docs/strategy-handbook.html`（手册 v2.1）、`config/settings.json`（现行参数）。

---

## 0. 定位澄清：这是半自动决策支持系统（写在最前）

现状：框架链路上游存在三个**人判环节**——T5 催化成色、物种 30 秒三问、探测层"真潜伏 vs 兑现残留"。这不是待修复的缺陷，而是系统的真实定位：

> **机器筛漏斗、算分、盯状态机；人做终审与催化判断。**

v0.2 起在 README 与手册中显式声明此定位，并给出人机分工表：

| 环节 | 机器 | 人 |
|---|---|---|
| 四维筛选 / ETF 榜 / 共振矩阵 | ✅ 全自动 | — |
| 蓄势分 / 突破价 / 认错价 | ✅ 全自动 | — |
| 观察池状态机推进 / 台账 | ✅ 全自动 | — |
| L1/L2 预警触发 | ✅ 全自动 | 确认检查 |
| T1-T4 主线判据 | ✅ 半自动 | — |
| T5 催化成色 | — | ✅ checklist（见 §3.2） |
| 探测层真伪分辨 | ✅ 量化辅助（见 §3.1） | ✅ 终审 |
| 物种判别终审 | ✅ 基本面闸自动拦截 | ✅ 三问终审 |

**收益**：消除"机器该兜底"的错觉；自动化建设聚焦真正可自动化的 70%。

## 1. 语义冲突裁决（改配置，不改思想）

以下三处是手册 / settings.json / history.json 之间的真实矛盾，v0.2 开发前必须在配置层裁决掉，否则代码会把矛盾固化。

### 1.1 探测层 × 启动档重叠区（chg20d 10~12）

**现状**：探测层 `0~12` 与启动档 `10~25` 重叠，同票同时命中"试错仓 1/3"与"建底仓"两种仓位语义。

**裁决：二者不是矛盾，是同一仓位阶梯的两个台阶——统一成一张阶梯表。**

| 台阶 | 触发 | 仓位 |
|---|---|---|
| 试错 | 探测层信号（资金背离，chg20d 0~12） | 1/3 |
| 底仓 | 同票出现二级确认（金叉/蓄势分≥60）**或** chg20d 进入 10~25 且四维≥3 | 2/3（含试错仓） |
| 满仓 | chg20d 25~60 主升档 + 四维全绿 | 3/3（≤总资金 20%） |

settings.json 的 `position_tiers` 改为**仓位阶梯的声明处**，手册三级火箭的"1/3→2/3→3/3"与之合并成同一张表，删除两处各自为政的表述。

### 1.2 确认层上限 90 vs 高位档 60 只看不追

**现状**：确认层筛到 `chg20d 25~90`，但 60~90 区间的票落进高位档被判"只看不追"——白筛 30 个点。

**裁决：确认层买入筛选收敛为 `25~60`；60+ 一律归高位档。持有判据不设区间**（四维用于判断"是否继续拿"，与买入区间无关——这正是三级火箭第三级的设计本意，参数上落实它）。同时手册四维动量维 `15~60` 与确认层 `25~90` 两套区间合并为：**动量维筛选区间 = 确认层区间 = 25~60**，探测层另用 0~12（职能不同，不合并）。

### 1.3 生命周期词汇：两套话语体系并存

**现状**：settings/手册用「预热/确认/扩散尾声/退潮」，history.json/dashboard 用「刚起步/主升/尾声/退潮」。四处字典互相对不上。

**裁决：正式词汇 = 机器友好的四阶段，旧词做映射兼容。**

| 正式词汇（v0.2 起唯一标准） | 旧词（历史数据兼容映射） |
|---|---|
| 预热 | 刚起步 |
| 主升 | 确认 |
| 尾声 | 扩散尾声 |
| 退潮 | 退潮 |

history.json 已有回溯数据**不回改**，读取层做映射；settings.json 的 `mainline.lifecycle` 键名按正式词汇重写。dashboard 的 `stage_cls` 映射同步更新。**理由**：历史台账与驾驶舱是"正在使用的数据面"，回改成本高；且「主升」比「确认」更直白——手册本来就强调人话。

### 1.4 参数 schema 统一（连带修复）

- `species_hard_gate.pe_ttm_reject: "negative_or_gt_80"` → 改为可执行结构 `{"pe_ttm_min": 0, "pe_ttm_max": 80}`
- `state_machine.r_unit: "单票目标仓位的 1/3"` → 改为 `"r_unit": 0.3333`（数值），注释保留人话
- 所有阈值必须是数值或结构体，**禁止自然语言字符串混入参数**

## 2. 验证体系：从 n=1 到可校准

**现状**：60+ 参数，验证只有航运单线 45 天回放（n=1）。这是 v0.2 最大的风险敞口——参数不是"已校准"，是"未证伪"。

### 2.1 三市况回放清单

航运回放是"教科书式主线"（清晰催化+量价齐升），不能代表全部市况。v0.2 验收前补两类回放：

| 市况 | 选例标准 | 重点验证 |
|---|---|---|
| 轮动市（主线快速切换） | 2026 年任一"主线寿命 <10 交易日"的时段 | 探测层假信号率、时间止损（10 日）触发频率 |
| 无主线缩量市 | 任一"终池 = 0"持续 ≥5 日的时段 | 空仓纪律、`pool_empty_action` 是否有效拦截 |

### 2.2 每个参数块登记"失效信号 + 重校触发器"

现有 `risk_switches` 只有探测层一条（假信号率 >70%）。扩展到全部参数块，进入 settings.json：

| 参数块 | 失效信号 | 动作 |
|---|---|---|
| probe（探测层） | 滚动 20 笔假信号率 >70% | 重校阈值（已有） |
| vcp（蓄势分） | 突破前蓄势分≥75 的票中，突破成功率 <40% | 调 mature_score 或 windows |
| score_alert L2 | 确认后 3 日内假信号率 >50% | 收紧 vol_ratio_min |
| state_machine | 单笔期望值连续 10 笔 < 0 | 冻结新开仓，全量复盘 |
| etf_funnel | 共振区信号 20 日后 ETF 回撤 >15% 占比 >50% | 收紧 chg20d_max |

### 2.3 v0.2 纸面验收标准（量化，达标才固化参数）

- **时长**：≥20 个连续交易日，覆盖 ≥2 种市况（§2.1）
- **信号量**：探测层累计 ≥15 笔、观察池状态机流转 ≥10 次（样本不足则延长）
- **探测层**：实际假信号率记录在案，与 50% 基准偏差 ±10pct 内视为通过
- **L1/L2**：航运两案例（08-10 假 / 09-07 真）在回放中必须持续被正确拦截/放行
- **蓄势分**：与实际突破的提前量分布，中位数 ≥2 个交易日
- **期望值**：纸面台账每笔记录 R 倍数，期末合并期望 > 0
- **任一参数块触发 §2.2 失效信号** → 该块回滚 v0.1 参数并记录原因，不影响其他块

## 3. 探测层增强：把"人判"量化一半

### 3.1 真潜伏 vs 兑现残留 → 「潜伏纯度分」（0~100，进入探测层输出）

现状此环节全靠人眼。三个子判据可量化，机器先打分、人只审边界案例：

| 子判据 | 真潜伏（加分） | 兑现嫌疑（减分） | 权重 |
|---|---|---|---|
| 价格分位：收盘价在 60 日区间位置 | <40% | >70% | 40 |
| 流入持续性：5 日中净流入天数占比 | ≥4/5 日 | 单日流入占 5 日总量 >60%（脉冲） | 35 |
| 资金结构：主力 vs 散户净流向 | 主力入 + 散户出（吸筹形态） | 主力、散户同入（派发嫌疑） | 25 |

- 纯度分 ≥70：正常进试错仓流程
- 40~70：减半试错仓，人工复核
- <40：不进观察池（探测层信号直接作废记台账）

### 3.2 T5 催化成色 checklist（保留人判，但给出结构）

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 商品价格 / 业绩 / 订单等**硬锚** | 至少一项有可验证的数据源 |
| 2 | 催化的可重复发酵性 | 未来 3 个月内 ≥2 个可预期的二次催化节点（财报/政策窗口/行业事件） |
| 3 | 催化新鲜度 | 首次发酵 ≤10 个交易日（老催化 = 尾声风险） |
| 4 | 反例排除 | 题材已被官方定调"过热"或龙头已发异动公告 → 不通过 |

T5 四项全过才算必要条件成立。**好处**：把"可反复发酵"从感觉变成四道可勾选的闸。

## 4. 共振层加强：ETF 互证的增量深挖

### 4.1 互证强度分级（共振 ≠ 满分一刀切）

现行规则：共振区个股主线强度维直接满分——太粗。共振内部同样分层：

| 档位 | 判据 | 评分处理 |
|---|---|---|
| **强互证（α）** | 个股 chg20d **>** ETF chg20d，且 ETF 量能未萎缩 | 主线强度维满分（现行规则，收窄到这一档） |
| **纯贝塔（β）** | 个股 chg20d ≈ ETF（±3pct 内） | 主线强度维打 7 折——赚的是板块贝塔，均值回归随时发生 |
| **弱于贝塔** | 个股 chg20d < ETF chg20d − 3pct | 共振降级为"预热区"，进观察池 |

**理由**：共振的本质是"板块在动"的证据，但选股赚的是超额部分。跟着 ETF 齐涨的票不值得满分。

### 4.2 同主题仓位上限（共振信号的隐性同质化）

共振区产出的信号天然集中在同主题（ETF 锚定决定）。新增 settings 参数：

```json
"resonance_concentration": {
  "max_stocks_per_theme": 2,
  "max_theme_exposure_pct": 30
}
```

单主题（同一 ETF 锚定）最多 2 只、总敞口 ≤30%。防止"共振区 6 只票全是航运"的伪分散。

### 4.3 无主线期的产出设计（空转不是缺陷，但要给人看的东西）

手册已承认市场大部分时间无主线（`pool_empty_action: 仅观察`）。v0.2 的日报在无主线期必须输出：

- 候补预热区清单（L1 异动票 + 探测层纯度分 ≥70 的票）——**下一轮主线的种子名单**
- 上轮主线退潮后的资金去向 Top5 板块（T2 榜的连续观察）

**收益**：把"空仓等待"从心理煎熬变成有产出的跟踪流程，防手痒。

## 5. 指数环境开关（独立于主线维度的第二道闸）

手册现有失效条件只覆盖主线维度（终池膨胀/空池）。补指数维度，三档调制：

| 大盘状态（沪深300） | 调制 |
|---|---|
| 站上 MA20 | 全参数生效 |
| MA20 下方、MA60 上方 | 探测层试错仓减半；确认层/主升档正常 |
| 跌破 MA60 | 全系统只跟踪不下单（观察池照常推进，供回暖后快速启动） |

settings 新增：

```json
"index_switch": {
  "index_code": "sh000300",
  "tier1_ma": 20,
  "tier2_ma": 60,
  "actions": ["正常", "试错仓减半", "只跟踪不下单"]
}
```

**理由**：探测层在指数下行期的假信号率会系统性抬升（资金背离多为反弹脉冲），这是手册"探测层假信号率 50%+"未区分市况的补丁。

## 7. 实施顺序建议（v0.2 开发顺序）

```
① 语义裁决落配置（本文 §1 全部 → settings.json + 手册同步改）      —— 半天
② 板块接口契约定稿（base.py 增 2 方法：sector_of / sector_flow_rank）
   —— 契约先行，实现可以后补
③ run_daily 最小闭环（正向漏斗 + ETF 榜 + 日报 HTML，暂不含状态机）
   —— 数据源以真实可用者为准，E2/E3 随手修
④ 状态机 + history.json 读写自动化（含 schema 固化，修 E5/E7）
⑤ §2 验证体系上线，纸面跑 ≥20 交易日
⑥ 达标后：§3/§4/§5 增量参数进入实验开关（shadow mode 并行输出，不直接参与决策）
⑦ 实验参数达标 → 转正，v0.2 固化
```

**纪律重申**：先跑两周再调权重的原则适用于本文所有新增参数——§3~§5 的增量一律先进 shadow mode，纸面验证达标才允许影响真实决策。
